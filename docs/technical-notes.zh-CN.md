## 视觉方案演进

### 第一代：分离定位与字符识别

初始流程先检测圆形棋子，再裁剪、判断颜色并分类汉字。历史本地工程 `PythonProject1` 包含霍夫圆处理与 `ChessResNet18`：在预训练 ResNet-18 上改为单通道输入，采用含 256 单元隐藏层和 dropout 的 11 类分类头。

合成字模方便生成样本，却未充分覆盖俯视相机中的模糊、反光、透视及低分辨率字符；霍夫圆的灵敏度也受光照影响。这些问题推动了真实图像采集。早期本地代码属于研发历史，未完整收录在当前仓库。

### 第二代：实拍数据与多类别 YOLO

刘超然独立完成实拍视觉数据采集及手工标注。团队记录包括原 40 × 40 cm 墨绿色软棋盘约 500 张图，以及更换 35 × 35 cm 米色软棋盘后的约 120 张。缩小棋盘是为解决原机械可达范围问题，但背景改变又引入了视觉域变化。

本地数据导出经历多个 Roboflow 版本。随后 `PythonProject2` 中的历史标签转换脚本把全部棋子类别改为单一类别，为定位优先的方案准备数据。

当前[训练脚本](../recognition/train.py)配置输入尺寸 1280、最多 200 轮、batch size 4、GPU device 0，并请求旋转、平移、缩放、剪切、透视、翻转、Mosaic、MixUp、随机擦除、copy-paste、HSV 扰动、分类损失加权及标签平滑。配置存在不等于每个 Ultralytics 版本、每类任务均实际应用所有选项，复现还需软件版本、权重、数据及训练日志。

相似汉字在实机距离下仍难稳定识别。把检测中心映射到棋盘坐标，不等同于先校正字符图像再识别，两者应分别描述。

图片用于说明数据标注过程，不作为独立测试集识别成绩。

### 第三代：定位与时序状态跟踪

课程交付方案把任务简化为定位棋子并跟踪已知开局下的变化，由软件棋盘维持棋子身份。人工确认用于选择比较盘面快照的时刻。

| 机制 | 作用 | 所在代码或版本 |
| :--- | :--- | :--- |
| 四点单应性 | 将相机坐标映射到列 0–8、行 0–9。 | 当前 `set_black_view`，使用 `cv2.findHomography`。 |
| 外扩 ROI | 四角点向外延伸 60 px，隔离多数盘外背景与弃子区。 | 当前 `calibrate`、`run`。 |
| 异步采集 | 后台线程保留最新帧，并请求驱动缓冲长度 1。 | 当前 `VideoStream`，没有零延迟测量保证。 |
| LAB 通道 CLAHE | 检测前增强局部对比度。 | 当前 `run`，clip limit 3.5、8 × 8 分块。 |
| 低亮度颜色启发式 | 根据检测框裁剪区推测黑棋朝向。 | 当前 `is_black_piece` 存在下述问题，不是 YOLO 颜色分类模型。 |
| 手动朝向选择 | 指定黑方底线对应图像哪一侧。 | 当前按键 `1`、`2`。 |
| 河界死区过滤 | 排除映射到河界装饰文字区域的检测。 | 当前阈值 `4.35 < y < 4.65`。 |

| 运动门控 | 中心点移动时清空初始化稳定窗口。 | 当前 `global_motion`，平方距离阈值 25。 |
| 轨迹能量 | 检出 +40、漏检 −15，能量大于 50 时计入。 | 当前 `piece_energy`。 |
| 历史众数 | 从最近 12 帧轨迹中选择最常见棋盘位置。 | 当前 `piece_history`、`Counter`。 |
| 数量与确认 | 允许预期数量或少一枚；空格确认走棋，初始化需超过 10 个稳定样本。 | 当前 `run`。缓冲容量 35 不等于每步都执行 35 帧投票。 |
| 占位与 ID 差分 | 从消失位置和 ID 变化推断起终点。 | 当前 `main.py` 的 `VisionAdapter.report_and_compare`。 |
| 运动期间抑制 | 机械臂运动时阻止走法上报，结束后重建基准。 | 当前适配器与调度器；摄像头仍持续采集。 |
| GUI 坐标倍率 | 把 640 × 360 显示点击放大两倍，对应预期的 1280 × 720 输入。 | `ui_main.py`，依赖实际尺寸及正确的显示映射。 |
| MOG2 手部运动检测 | 背景差分与运动区域门控。 | 较早 `localization/find_chess.py`，不在当前 V15.4 主路径。 |
| 快速位移旁路 | 平方距离大于 2500 时跳过平滑。 | 历史本地 `find2.txt`，当前 V15.4 未采用。 |
| 曝光与标定保存 | DirectShow/gain 设置及标定持久化试验。 | 历史本地版本；当前主入口重新标定。 |

按版本列出机制，可以保留技术积累而不混淆运行路径。ROI 不能排除区域内部的全部干扰，时序稳定也不保证每次吃子都能正确恢复身份。

### 第四代：校正后的棋盘网格分类

研发方向是先估计角点，再对归一化棋盘分类：

1. 准备本项目棋子图像及空盘图像。
2. 向交点合成棋子并同步更新标签。
3. 使用基于 RTMPose/MMPose 的模型估计四角点并校正透视。
4. 使用 Swin Transformer V2 与空间 neck/head，对 90 个交点进行 16 状态分类：红黑各七类、空位及其他/障碍物。
5. 先评估独立图像和连续序列，再把状态变化接入棋局与运动控制。

参考实现为基于 OpenMMLab 的 [TheOne1006/chinese-chess-recognition](https://github.com/TheOne1006/chinese-chess-recognition)。其中 `CChessMixSinglePngCls`、`CChess10_9Neck`、`CChessTableHead` 提供相关实现示例。本项目的数据准备、适配、训练和评估，应具体说明团队在这些基础上完成的工作。

参考角点配置采用 `KLDiscretLoss` 与 `SoftWeightSmoothL1Loss`；Swin 分类配置采用 `LabelSmoothLoss`，它们分别监督不同分支。

当前整机入口仍使用第三代。仓库未包含第四代专用训练产物、评测记录及整机适配器，因此研发方案不代表训练和全自主实机对弈已经完成。

参考项目的 `full-err-zero = 0.83` 表示其验证集约 83% 的盘面图中所有交点均正确，不是所有输入均无错误，也不是本项目实测成绩。

## 运动与硬件

### 几何与补偿

当前连杆参数为 `L1 = 73`、`L2 = 231`、`L3 = 231`、`L4 = 66` mm，格距 34.2 mm、河界间距 34.0 mm，`BOARD_ORIGIN_Y = 200`、`BOARD_Z = −33`、`SAFE_Z = 70` mm。配置值本身不证明全盘可达。

活动逆解在几何计算前采用以下经验补偿：

```text
comp_x = 1.125 * x
R_target = sqrt(comp_x² + y²)
R_comp = 0.94 * R_target
comp_z = z + 0.12 * R_target
delta_z = comp_z + L4 - L1
D = sqrt(R_comp² + delta_z²)
```

求解器检查两连杆可达条件，以余弦定理计算肩肘角，并约束手腕朝下。高度项属于随伸展距离变化的前馈补偿，不是已辨识的弹性模型或反馈控制器。本文不声明通用定位精度或逆解耗时。

`control.py` 将棋盘位置转换为毫米坐标，以名义 50 Hz 插补航路点；目标总位移不超过 0.1 mm 时，相应增量置零。抓放包括安全高度、8 mm 微距悬停、慢速垂直接近、磁铁通断和垂直撤离。吃子时先把被吃棋子送往弃子区。

### 电气接口

| 接口 | 当前实现 |
| :--- | :--- |
| PC 至舵机 | CH347 USB 桥接，I2C 地址 `0x40`，PCA9685。 |
| 通道 | 底座 0、肩 4、肘 8、腕 12。 |
| PWM | 预分频 121，约 50 Hz；各通道分别限制脉宽。 |

<a id="mathematical-models"></a>

## 数学模型与代码对应

以下保留理解工程实现所需的主要公式。它们解释当前代码，不单独构成准确率、速度或可靠性的证明。

### 单应性与棋盘映射

设相机像素齐次坐标为 p = (x, y, 1)，棋盘坐标为 q = (u, v, 1)。H 由四个角点估计，齐次归一化后得到棋盘交点坐标。单应性校正平面透视，不替代相机镜头畸变标定。

$$
\tilde{\mathbf{q}}=H\mathbf{p},\qquad u=\frac{\tilde q_1}{\tilde q_3},\quad v=\frac{\tilde q_2}{\tilde q_3}
$$

### ROI 与时序稳定

ROI 角点沿棋盘中心 C 的径向外扩 b = 60 px。中心点 EMA 系数为 0.28；当前代码仅在位移超过 1.5 px 时更新。12 帧离散位置历史采用众数选择，检测能量与数量门槛另见机制表。

$$
\mathbf{P}'_i=\mathbf{P}_i+b\frac{\mathbf{P}_i-\mathbf{C}}{\lVert\mathbf{P}_i-\mathbf{C}\rVert}
$$

$$
\hat{\mathbf{c}}_t=(1-\lambda)\hat{\mathbf{c}}_{t-1}+\lambda\mathbf{c}_t,\qquad\lambda=0.28
$$

### 解析逆运动学

记 R = R_comp、z = delta_z，分别对应前文补偿半径与高度差；D 为肩关节到等效腕部目标的距离。满足两连杆可达条件后，以余弦定理求解。下式角度用弧度；代码转换为度，并按舵机参考姿态加入偏置。当前腕部附加补偿系数为 0。

$$
D=\sqrt{R^2+z^2},\qquad |L_2-L_3|\le D\le L_2+L_3
$$

$$
\alpha=\arccos\frac{L_2^2+D^2-L_3^2}{2L_2D},\qquad\gamma=\arccos\frac{L_2^2+L_3^2-D^2}{2L_2L_3}
$$

$$
\beta=\operatorname{atan2}(z,R),\quad q_2=\beta+\alpha,\quad q_3=q_2-(\pi-\gamma),\quad q_4=-\frac{\pi}{2}-q_3
$$

### PWM 与走法选择

PWM 式中 u 为限幅后的微秒脉宽，先受各通道上下限约束，再映射到 PCA9685 tick。决策网络在规则模块返回的候选集合 M 中取最高分。这里的候选集合受当前规则实现范围限制。

$$
n=\left\lfloor\frac{u}{20000}\,4096\right\rfloor,\qquad a^*=\operatorname*{arg\,max}_{m\in\mathcal{M}} f(S)_{\operatorname{idx}(m)}
$$

<a id="game-decision"></a>

## 棋局决策与集成

`game/board.py` 实现盘面、棋子运动约束、候选走法枚举、回合切换、历史列表及将帅缺失时的结束判定；未实现完整的将军/将死裁定或通用悔棋 API。候选过滤的正确性受规则模块实现范围限制。

`ChessNet` 使用三层 3 × 3 卷积，通道为 14 → 64 → 128 → 128，再经过全连接层 11,520 → 1,024 → 8,100。输入为 14 × 10 × 9 棋子位置张量，输出索引为 `(source_row * 9 + source_col) * 90 + destination_row * 9 + destination_col`，从规则模块返回的候选中选择最高分走法。

当前决策路径没有 Minimax 或 Alpha–Beta 搜索。学习评分依赖 `game/aaa.pth`，缺少时明确回退到随机候选。网络定义本身不能证明训练后的棋力。

`main.py` 转换坐标、处理吃子、更新软件状态并调度动作；它没有测量每次实体落子是否成功。

## 验证与研发边界

团队记录的试验为**连续 20 步中 18 次覆盖目标交叉中心点**。引用时应保留样本量与判定标准，不能由此推导毫米误差、重复试验条件、识别准确率或整场对局可靠性。

数据量及历史行为来自团队研发记录。仓库未公开全部原图、运行日志及第四代独立测试集成绩。

| 项目 | 观察 | 对复现的影响 |
| :--- | :--- | :--- |
| 颜色与方向 | `is_black_piece` 用单通道像素数量除以三通道 `roi.size`，最大比值为 1/3，无法超过 0.5。 | 当前自动判向不能通过；修复验证前使用手动选择。 |
| GUI 视频 | GUI 设置 `ui_callback`，当前视觉未调用它。 | 内嵌视频链路未接通，仍需关注 OpenCV 窗口。 |
| GUI 棋盘 | 显示代码使用 `piece.name`、`piece.is_red`，盘面实际存储元组。 | 需要适配显示接口。 |
| 可达性与配置 | `tools/calc_reach.py` 的旧常量与当前配置、补偿不同；当前远端目标可能被逆解拒绝。 | 不能以此工具认证当前全盘可达，运行前需统一标定。 |
| 动作结果 | 插补过程没有把每次 `execute_move` 失败都上报为可验证的物理结果。 | 指令序列结束不等同于落子成功。 |

以上针对当前代码，不改变历史实机演示记录。

## 后续研发节点

- **视觉：**明确数据及变换流程，按实拍场景划分训练测试集，训练或微调，报告交点级与整盘级结果，测试吃子和遮挡，并验证整机状态适配。
- **运动：**统一配置和可达性计算，在近远端、边缘及中心重复测试，比较平滑加减速与当前插补。
- **决策：**验证运动约束、明确权重来源和棋力，再与负责人选择改进方案；自对弈强化学习属于探索选项。
- **集成：**补齐 GUI 接口，验证启动、停止、吃子恢复及状态同步。

新增结果应注明版本、硬件、数据/测试条件、指标、样本量和边界。参考实现保留其许可证，个人贡献具体对应本项目实际完成的工作。
