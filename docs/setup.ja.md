# ChessRobot セットアップと操作

[简体中文](setup.zh-CN.md) · [English](setup.en.md) · **日本語** · [プロジェクト概要](../README_JA.md)

現在の第3世代エントリーポイントを説明します。実機とその校正値が必要で、統合されたシミュレーション専用スイッチはありません。第4世代の学習は別の開発工程であり、[技術ノート](technical-notes.ja.md)を参照してください。

## 環境

- Windows 10/11、64-bit Python 3.10以上。
- CUDA対応PyTorchと互換性のあるNVIDIA環境。現行の視覚処理は`model.to('cuda')`を直接呼び、CPUへのフォールバックはありません。
- USBカメラ、WCH CH347ドライバ、対応する64-bit `CH347DLLA64.DLL`、PCA9685、4個のサーボ、電磁石とリレー。

`requirements.txt`はPyTorch、Ultralytics、OpenCV、NumPy、PyQt5の下限を示し、検証済み環境のロックファイルではありません。再現時には動作した版を記録します。過去の視覚スクリプトではPillowとフォントが必要な場合もあります。

PowerShellで実行します。

```powershell
git clone https://github.com/TJS-Git-Hub/ChessRobot.git
cd ChessRobot
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -c "import torch, cv2; print(torch.__version__); print(torch.cuda.is_available()); print(cv2.__version__)"
```

CUDAが利用できない場合は、視覚処理の起動前にPyTorchとドライバの環境を整えます。依存関係のインストールだけで実機動作が確認できるわけではありません。

## 必要なファイル

| ファイル | 配置 | 説明 |
| :--- | :--- | :--- |
| WCH DLL | ルートの`CH347DLLA64.DLL` | 対応するメーカーのライブラリとドライバを用意します。DLLはGitで除外され、クリーンなクローンには含まれません。 |
| 駒検出器 | `recognition/models/best.pt` | 重みは追跡対象ですが、クラス対応と視覚版の一致が必要です。名前だけでルートの`yolo11n.pt`に置換しないでください。 |
| 任意の着手選択重み | `game/aaa.pth` | 現在のツリーには含まれず、ない場合は候補からランダム選択。 |
| 校正配列 | `recognition/models/H_matrix.npy`、`ROI_corners.npy` | 過去のスクリプトで使用。現行の入口は対話校正を行います。 |
| YOLO学習データ | `recognition/data/data.yaml`と参照先 | 原画像と学習出力はGitから除外。学習前にパスとラベルを確認します。 |

第3世代の検出器は位置検出に使用し、駒の種類は標準初期配置と履歴から維持します。ファイル名は14クラス、量子化、学習性能の証明にはなりません。

## ハードウェアと校正

| 接続・設定 | コード |
| :--- | :--- |
| CH347 device index 0、PCA9685 I2C `0x40` | `hardware.py` |
| 0 / 4 / 8 / 12：ベース / 肩 / 肘 / 手首 | `config.py` |
| GPIO2マスク`0x04`からリレー制御 | `hardware.py` |
| 基準パルスとチャネルごとの上下限 | `config.py`の`SERVO_CONFIG` |
| 盤原点、間隔、盤面高さ、待避高さ | `config.py` |
| 横方向・半径・高さの経験的補償 | `kinematics.py` |

実際の組立に合わせて、盤、サーボ電源、共通基準、リレー配線を確認し、盤外の駒置場も検証済み動作範囲内に配置します。コントローラ生成時に`go_to_wait()`が呼ばれ、直ちに運動指令が出ます。

次のツールはそれぞれ異なる動作をします。

```powershell
python tools/calibrate_servo.py
python tools/test_electromagnet.py
python tools/calc_reach.py
```

- `calibrate_servo.py`はサーボを動かし、パルスの粗調整・微調整を受け付け、`config.py`へ転記する値を表示します。自動保存はしません。
- `test_electromagnet.py`は実際のリレーと電磁石を操作します。
- `calc_reach.py`は現行の `board_to_physical` と `solve_ik` を使い、機器を開きません。現在は90目標中11点を拒否し、拒否があれば非ゼロで終了します。幾何学的到達だけではサーボ範囲、衝突回避、把持成功を保証しません。

全盤対局を試す前に機構設定を統一し、有効な逆運動学で個々の目標を確認します。遠端の点が到達条件を満たさない場合があります。リポジトリの値を別の実機の校正値と見なさないでください。

## CLIの操作

1. 検出重み、DLL、ドライバ、校正済みの実機を準備します。`VideoStream`の既定カメラは`1`、要求画像は1280 × 720です。収集スクリプトは`0`なので、実際の機器に合わせます。
2. 32個の駒を標準初期配置に置き、アームは黒側の基線後方に配置します。
3. 起動します。

   ```powershell
   python main.py
   ```

4. OpenCV窓で左上、右上、右下、左下の順に盤の4隅をクリックします。
5. 必要なら向きを手動指定します。`1`は黒側が画像の遠方・上側、`2`は近方・下側です。明度比率は単一チャネルの画素数で計算するよう修正済みですが、実照明での向き判定は実測が必要です。
6. 初期化を待ちます。人間が赤側で先手です。着手後に手を除き、視覚窓にフォーカスして**Space**を押します。
7. ロボットが応手を選んで移動し、待機位置へ戻って視覚の基準を更新します。駒取りでは先に相手駒を盤外へ搬送します。
8. 視覚窓の`q`またはCLIの割込みで終了します。終了処理は停止とインターフェースの解放を行い、待機位置への運動を開始しません。ソフトウェア停止はハードウェアの電源遮断を保証しません。

基準の固定中は駒の個数や位置を変えないでください。駒取りでIDが混同すると、攻撃側の駒を一度持ち上げて戻し、再確定するよう表示される場合があります。実盤とソフトウェアの状態が食い違った場合は、一致した配置に戻して再初期化します。回復は完全自動ではありません。

## GUI試作

```powershell
python ui_main.py
```

「開始対弈」ボタン、ソフトウェア停止、ログ、Space/1/2操作を備えます。開始ボタンは同じ実機コントローラを生成します。

GUIは校正・追跡フレームを受信し、実フレーム、縮小画像、余白に基づいてクリック座標を変換します。盤面はロック付きスナップショットの `(side, kind)` を描画します。停止要求は撮影と補間を終了させ、終了処理では原点復帰を開始しません。カメラ・Qt・OpenCVの連携と校正精度は実機での確認が必要です。

## トラブル対応

| 症状 | 確認事項 |
| :--- | :--- |
| DLL読込み・CH347接続失敗 | Windows/Python/DLLのbit数、ドライバ、ライブラリ位置、USB接続、機器番号。 |
| カメラが開かない・別の映像 | 番号、他プロセスの使用、接続、実際の解像度。 |
| CUDAエラー | PyTorch構成、NVIDIA環境、CUDA可用性。自動CPU切替はありません。 |
| 向き・基準が決まらない | 手動1/2、角点順、検出器、初期配置、検出の安定性。 |
| 人間の着手後に動かない | フォーカス、Space、駒数、ID、直前の基準盤面。 |
| ランダム・不自然な応手 | `game/aaa.pth`の有無と互換性。ルール判定も競技用に完全ではありません。 |
| GUI映像なし・盤面例外 | 取得フレーム、校正クリックの変換、ログを確認します。コールバックとタプル盤面は修正済みで、Qt・カメラ連携は実機確認が必要です。 |
| 到達不能・配置ずれ | 現行寸法、盤原点・高さ、逆解補償、サーボ校正、パルス制限。現行の `tools/calc_reach.py` と実測寸法を確認します。 |

## 再現結果の記録

コード版、Pythonと依存関係の版、検出・着手選択の重み、カメラ設定、盤寸法、補償値、使用した入口を記録します。配置試験では標本数と中心被覆・距離の基準を示します。認識評価は独立した実画像を使い、交点単位と盤面単位の精度を区別します。既存の結果と今後の工程は[技術ノート](technical-notes.ja.md)を参照してください。

2026-10-24：移動前に始点・終点の配置点、8 mm待避点、安全高さを検査します。駒取りでは盤外置場と自駒の始点も検査し、既知の到達不能点があれば最初の運動・吸着前に拒否します。各補間区間の検査は継続しますが、全動作の衝突保証ではありません。オフライン回帰9件が通過しました。校正値は変更せず、現行IKは引き続き11/90目標を拒否するため、実測が必要です。
