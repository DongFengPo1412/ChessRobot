## 1. 系统概述与硬件工装制作

本项目构建了一套兼具桌面便携性与高稳定性的实体对弈机器人平台，由团队成员自主设计、装配、制作与编程实现。

### 1.1 实体棋盘与棋子制作细节
- **定制棋盘物理选型与演进**：
  - **初版淘汰（ 40 × 40 cm  墨绿色软盘）**：初期采购了 40 × 40 cm 墨绿色软质棋盘，但在四自由度机械臂联合调试中发现，受制于机械臂连杆长度与工作空间边界（大臂 $L_2 = 231$ mm、小臂 $L_3 = 231$ mm），末端电磁铁**无法触及远端第 9 排（红方底线）的外侧边缘格点**（超出理论极限作业半径），因机械干涉与行程不足而果断淘汰；
  - **定型版本（ 35 × 35 cm  米黄色软盘）**：重新定制了规格为 35 × 35 cm 的米黄色软质便携棋盘（软盘），网格线宽精准，格点中心间距压缩至约 34.2 mm （与底层驱动 `config.py` 中的 `SQUARE_WIDTH = 34.2`、`BOARD_ORIGIN_Y = 200.0` 严密吻合），机械臂刚好能够稳定且平顺地覆盖全盘 90 个交叉点。
- **纯手工自制导磁棋子**：
  - 选用标准加粗微软雅黑字体设计红黑双方共 32 枚棋子图案，严格设定圆形图纸直径为 3.0 cm；
  - 打印图纸后逐个手工精准裁剪；
  - 采购直径为 3.0 cm、厚度适中的圆形金属导磁铁片，将裁剪好的字贴平整粘贴在铁片正面，制成专用的导磁象棋棋子。
- **末端执行机构与抓取方式**：
  - 机械臂末端配备 5V 直流吸盘电磁铁，通过板载继电器进行通断电控制；
  - 吸取棋子时，机械臂垂直下探至棋子上方，继电器吸合通电，电磁铁牢固吸附棋子铁片；
  - 到达目标格点后，继电器断开消磁，棋子平稳释放就位。

### 1.2 实测对弈精度与考核指标
运动控制的核心指标在于**轨迹防刮蹭避碰**以及**棋子在目标网格交叉中心点的覆盖度**。  
在系统的连续 20 步实机走棋测试中：
- **18 次精准覆盖** 棋盘网格交叉中心点；
- **仅 2 次微偏** 未完全居中覆盖；
- **落子中心覆盖成功率达到 90%**，整机运行平稳流畅，无碰倒相邻棋子现象。

### 4.1 机械与运动控制模块 (田峻硕负责，刘超然辅助调试)

机械臂采用四自由度关节型串联构型：底座水平回转关节（J1）、大臂俯仰关节（J2）、小臂俯仰关节（J3）与腕部姿态保持关节（J4），末端挂载微型电磁铁吸盘（强制保持垂直向下， $\phi = -90^\circ$ ）。

#### 1. 物理连杆几何参数 (`config.py`)
- 底座回转中心高： $L_1 = 73.0$ mm
- 大臂有效连杆长： $L_2 = 231.0$ mm
- 小臂有效连杆长： $L_3 = 231.0$ mm
- 腕部关节至吸盘端长： $L_4 = 66.0$ mm

#### 2. 运动控制核心算法清单

- **算法 1：闭式几何解析逆运动学求解算法 (Closed-Form Analytical Inverse Kinematics Formulation)**：
  - **核心原理**：为杜绝数值迭代法（如 Jacobian 伪逆法）在连杆奇异点附近的发散抖动与毫秒级延迟，系统将三维空间笛卡尔位置解耦为**水平航向回转平面**与**垂直俯仰平面**。在腕部强制保持垂直向下（ $\phi = -90^\circ$ ）几何约束下，利用余弦定理（Law of Cosines）直接推导几何解析封闭解，单次解算耗时 < 0.1 ms；
  - **数学建模**：
    - **底座航向角解算**：
      $$\theta_1 = \text{atan2}(X_{\text{comp}}, Y), \quad t_1^{\text{deg}} = \text{degrees}(\theta_1) + 90.0^\circ$$
    - **等效俯仰连杆弦长**：
      $$\Delta Z = (\text{comp}_z + L_4) - L_1, \quad D = \sqrt{R_{\text{comp}}^2 + \Delta Z^2}$$
    - **余弦定理求大臂内角 $\alpha$ 与小臂内角 $\gamma$**：
      $$\cos(\alpha) = \frac{L_2^2 + D^2 - L_3^2}{2 L_2 D}, \quad \cos(\gamma) = \frac{L_2^2 + L_3^2 - D^2}{2 L_2 L_3}$$
    - **关节绝对与相对角度映射**：
      $$\beta = \text{atan2}(\Delta Z, R_{\text{comp}})$$
      $$t_2^{\text{deg}} = \text{degrees}(\beta + \alpha), \quad t_3^{\text{deg}} = t_2^{\text{deg}} - (180.0^\circ - \text{degrees}(\gamma)), \quad t_4^{\text{relative}} = -90.0^\circ - t_3^{\text{deg}}$$

- **算法 2：多源非线性前馈补偿控制律 (Multi-Source Nonlinear Feedforward Compensation Law, `kinematics.py`)**：
  - **核心原理**：针对开环数码舵机传动齿隙虚位、长悬臂受自重及负载引起的弹性弯曲下垂，在逆解前级注入三维解耦前馈补偿律；
  - **补偿控制方程**：
    - **$X$ 轴横向几何比例放大前馈**：放大侧向旋转角以克服边缘列机械行程衰减，
      $$X_{\text{comp}} = X \times K_x \quad (K_x = 1.125)$$
    - **合成工作半径力矩收缩修正**：
      $$R_{\text{target}} = \sqrt{X_{\text{comp}}^2 + Y^2}, \quad R_{\text{comp}} = R_{\text{target}} \times (1 - K_r) \quad (K_r = 0.06)$$
    - **长悬臂重力弹性挠度高度前馈**：力臂越长下垂量越大，通过线性前馈强制抬升目标高度以抵消形变，
      $$\text{comp}_z = Z + (R_{\text{target}} \times K_z) \quad (K_z = 0.12)$$
    - **底座行程比例增益增补（Base Gain Scaling）**：
      $$u_0 = u_{0,\text{ref}} - (t_1 - 90.0^\circ) \times K_{\text{deg}} \times K_{\text{base}} \quad (K_{\text{base}} = 1.0)$$

- **算法 3：微距五阶段防刮蹭轨迹规划算法 (5-Phase Micro-Approach Trajectory Planning, `control.py`)**：
  - **核心原理**：中国象棋棋盘格间距仅为 35mm，棋子直径约 30mm，相邻缝隙不足 5mm。若吸盘斜向入位极易撞翻邻近棋子。因此轨迹被严格分段为五阶段空间航路点：
    1. **巡航平移段**：快速平移至棋子正上方安全巡航高度 $Z_{\text{safe}} = 70.0$ mm；
    2. **微距悬停对准段**：垂直下探至棋子表面上方 8mm 处悬停（ $Z_{\text{micro}} = -25.0$ mm ），延时 0.3s 等待手腕姿态绝对竖直稳定；
    3. **慢速垂直切入吸附段**：慢速下探至盘面 $Z_{\text{board}} = -33.0$ mm，使能电磁铁吸起棋子，延时 0.5s 建立稳定磁力；
    4. **小臂主导纯垂直微抬段**：慢速纯垂直抬升 8mm 返回 $Z_{\text{micro}}$，彻底杜绝斜向离盘将相邻棋子刮倒带偏；
    5. **巡航转移与对称释放段**：垂直拉升至 $Z_{\text{safe}}$ 后平移至目标格，并在目标点执行相同的微距垂直下探、断电退磁与纯垂直微抬；
  - **吃子弃子序列**：若触发吃子，先规划拾取被吃棋子并运送至棋盘外弃子区（Graveyard，坐标 (220, 120, BOARD_Z + 20)）释放，再执行进攻棋子的位移序列。

- **算法 4：线性插补规划与 0.1mm 浮点死区截断控制 (50Hz Linear Interpolation with 0.1mm Deadzone, `move_to_smooth`)**：
  - **核心原理**：插补器以 50Hz 频率（`steps = int(duration * 50)`）执行空间线性插值。在纯垂直升降过程中，由于逆运动学浮点计算的微小数值舍入误差，XY 轴在理论位移为 0 时仍可能计算出 $10^{-4}$ mm 级的微小扰动，导致底座舵机出现高频抖动；
  - **死区截断律**：
    $$\Delta X_{\text{step}} = \frac{X_{\text{target}} - X_{\text{cur}}}{\text{steps}} \quad (|X_{\text{target}} - X_{\text{cur}}| \ge 0.1\text{ mm})$$
    强制切断小于 0.1 mm 的水平伪位移，确保升降阶段底座舵机输出纯零信号，杜绝横向刮碰。

- **算法 5：12 位 PCA9685 PWM 脉宽量化与硬件驱动映射模型 (`hardware.py`)**：
  - **核心原理**：主控经 CH347 高速 USB 桥接芯片以 100KHz I2C 总线控制 PCA9685 驱动板。配置系统预分频器为 121 实现 50 Hz 伺服基频（周期 $T = 20$ ms ）；
  - **脉宽量化计算**：
    $$\text{tick} = \left\lfloor \frac{\text{clamp}(u, u_{\min}, u_{\max})}{20000} \times 4096 \right\rfloor$$
    将目标微秒脉宽精确映射为 12 位寄存器计数值并以流式单次写入；同时由 CH347 原生 GPIO2 控制继电器以纳秒级响应驱动末端微型电磁铁。

#### 3. 机械与运动控制的未来优化方向
下一步将重点优化多轴插补轨迹算法，引入 S 曲线平滑加减速控制，进一步抑制远端机械抖动，确保复杂长距离移位时末端落点更加平稳。

### 4.2 视觉感知模块及四代演进历程 (刘超然独立负责)

视觉模块由刘超然独立负责全部数据集采集、数据标注以及算法研发。整个视觉方案历经四代迭代与工程试错，形成了丰富的技术积累与自研资产：

#### 第一代原型 (Gen 1: 霍夫圆检测 + 合成字模 OCR 探索)
- **方案构想与试错探索**：
  早期尝试利用传统几何图像处理算子检测圆形棋子。在开发过程中进行了两次内部试错演化：
  - **试错 1（一体化 CNN 识色识字）**：设计单个 CNN 网络同时预测棋子阵营与汉字，但在镜头边缘畸变与反光影响下，色彩与字符特征相互干扰，损失函数难以收敛；
  - **试错 2（任务解耦：HSV 识色 + 独立 CNN 识字）**：剥离阵营判别，改用 HSV 空间阈值判断颜色，CNN 仅负责汉字识别。
- **第一代核心算法清单**：
  - **1. 霍夫梯度圆变换检测算法 (Hough Gradient Circles Transform, `cv2.HoughCircles`)**：
    基于 Sobel 梯度幅值与累加器空间极大值投票，定位棋子圆形外边框与几何圆心 $(x_c, y_c)$ 及半径 $r$；
  - **2. HSV 色彩空间双边阈值分割算法 (HSV Color Space Bilateral Thresholding)**：
    解耦光照强度（V 通道）与色彩本征（H 通道），通过设定红方双峰区间与黑方低饱和度区间的双向阈值掩膜，快速完成红黑阵营物理初筛；
  - **3. 自动化字模合成与二阶段级联 CNN 字符分类 (Automated Font Synthesis & Cascaded CNN OCR)**：
    编写 Python 脚本自动调用 Microsoft 微软雅黑加粗字体，渲染合成 1000 余张白底红/黑汉字字模图，训练轻量级 CNN 字符分类器，串联圆心截取 ROI 进行二级汉字推断。
- **彻底废弃的客观根因**：
  - **缺乏真实样本导致严重域漂移**：训练完全基于理想合成字模，在真实俯拍模糊与倾角下识别率不足 20%；
  - **高空小尺度特征严重失真**：工业相机需俯瞰全盘因而架设位置较高，截取出的单个霍夫圆棋子分辨率极低，汉字笔画严重模糊粘连；
  - **几何算子鲁棒性极差**：霍夫圆对环境光斑与棋盘木纹极度敏感，调低阈值假圆丛生，调高阈值暗角漏检。

#### 第二代演进 (Gen 2: YOLOv11 细粒度 14 类目标检测与数据工程)
- **方案构想与真实高空数据采集**：
  彻底放弃传统几何算子，转向前沿目标检测深度学习架构。自主设计全套数据采集流程与标注规范：
- **第二代核心算法与数据工程清单**：
  - **1. 40cm 高空对弈场景图像采集协议 (`collect_real_data.py`)**：
    将工业高清相机刚性固定于对弈实机正上方 40 cm 处，以恒定 1280×720 分辨率采集 620 张覆盖全盘空局、对弈中局、残局以及手部遮挡全周期的真实高空图像；在 **Roboflow** 平台上逐张精细标注 14 类兵种目标框（每张 32 颗棋子），构建本地棋盘数据集；
  - **2. 极限空间与光影混合数据增强流水线 (Extreme Hybrid Augmentation Pipeline, `train.py`)**：
    为提升模型在苛刻工业现场的抗干扰能力，在本地 **RTX 4060** 上微调训练 YOLOv11n 时构筑了极致增强流水线：
    - **空间几何仿射**： $\pm 45^\circ$ 任意角度旋转（`degrees=45.0`）、±15% 空间平移、±60% 尺度缩放、 $\pm 15^\circ$ 剪切拉伸与水平/垂直镜像翻转（`fliplr/flipud=0.5`）；
    - **混合与遮挡模拟**：Mosaic 1.0 满幅拼接、MixUp 0.2 线性插值混合、Random Erasing 0.4（随机矩形擦除，专项模拟机械臂长力臂投射阴影与手部遮挡）与 Copy-Paste 0.2；
    - **光影与色度抗性**：HSV 饱和度（`0.5`）与明度（`0.4`）大幅扰动，强制模型剥离反光干扰；
  - **3. 细粒度损失加权与标签平滑正则化 (Class Loss Re-weighting & Label Smoothing)**：
    针对汉字笔画结构相似度高的特点，设置分类损失倍率 `cls=2.5` 强化梯度回传，引入 `label_smoothing=0.1` 抑制高置信度过拟合。
- **实战表现与跨棋盘域偏移痛点 (Domain Shift)**：
  - **目标定位精度极高**：彻底解决了霍夫圆伪检与漏检问题，棋子边界框回归稳定；
  - **底色域突变破坏泛化（Domain Shift）**：前期 500 张样本在墨绿色软盘上采集，后期因工期突换为浅米黄色棋盘，新增补充样本仅 120 张，底色剧变导致强烈色彩域偏移；
  - **未拉伸前斜视透视畸变导致单字分类失效**：**当时系统尚未引入单应性正投影展开**。斜视镜头远端的棋子受透视压缩，小尺度笔画严重模糊变形，“車”与“卒”、“馬”与“兵”等相似字混淆严重。由于博弈决策对单字容错率为零，该方案无法直接支撑实机对弈。

#### 第三代实战 (Gen 3: 战略性降维 —— YOLO 定位 + 红黑阵营二分类 + 核心工程补丁矩阵)
- **战略取舍与工程减法**：
  面对结题交付工期与未展开斜视字形细分的物理瓶颈，做出关键取舍：将 YOLO 任务战略性降维为**单类别棋子定位（`nc: 1, names: ['piece']`）结合颜色/规则推断**；中心点经单应性变换映射至 10×9 离散网格，仅将起止坐标差分（如 `e6 -> e4`）报送决策大脑。该方案在实机交付中达成了极高定位精度。
- **自研核心视觉算法矩阵（十六项工程落地机制）**：
  为彻底克服实机对弈中由环境反光、人手遮挡、舵机震动及规则死锁引发的各种扰动，在第三代中自研构建了完备的算法矩阵：
  - **1. 顺时针四点 SVD 单应性透视变换算法 (Clockwise 4-Point SVD Homography Matrix Estimation, $\mathbf{H}$ )**：
    启动时顺时针点击棋盘物理四角点（TL $\to$ TR $\to$ BR $\to$ BL），基于奇异值分解（SVD）解算单应性矩阵 $\mathbf{H}$，将斜视视角坐标精准正交投影至 $10 \times 9$ 规范化网格矩阵，计算中心点逻辑落格；
  - **2. 径向单位向量外扩 ROI 多边形掩膜阻断算法 (Radial Vector Outward Extrusion, `expanded_roi`)**：
    从棋盘几何质心 $\mathbf{C}$ 向四角点计算径向单位向量 $\mathbf{u}_i = \frac{\mathbf{P}_i - \mathbf{C}}{\|\mathbf{P}_i - \mathbf{C}\|}$，沿外向平移 60 像素缓冲带，利用 `cv2.fillPoly` 与 `cv2.bitwise_and` 生成二值掩膜，**将棋盘外完全置零屏蔽**。当机械臂吃子后将弃子放置于右侧外部弃子区（Graveyard）时，**场外死子被掩膜物理阻断，杜绝幽灵死子误检**；
  - **3. MOG2 高斯混合背景差分动态遮挡检测算法 (MOG2 Dynamic Hand Occlusion Detector, `find_chess.py`)**：
    构建 500 帧历史背景模型与方差阈值 120，降采样至 $640 \times 360$ 加速处理。将前景掩膜与棋盘 ROI 求交，提取最大连通轮廓面积；当连通轮廓面积超过 2000 px² 时，判定人手正进入盘面走棋，立即置位 `is_occluded = True` 触发物理层告警并冻结盘面状态；
  - **4. 异步单缓冲零延迟流引擎与硬件熔断机制 (Zero-Latency VideoStream Engine & Hardware Failsafe)**：
    开辟独立守护线程循环拉取视频流，设置底层驱动缓冲区为 1（`CAP_PROP_BUFFERSIZE = 1`），根除多线程图像队列堆积造成的时序延迟；主推理循环嵌入 `if vs.stopped: break` 硬件存活哨兵，控制台急停时即刻安全熔断退出，杜绝后台僵尸流与死锁；
  - **5. LAB 色彩空间 CLAHE 自适应局部直方图均衡化 (CLAHE in LAB Color Space)**：
    图像输入推理前转换至 LAB 空间，对 L 亮度通道执行限制对比度自适应直方图均衡化（`clipLimit=3.5, tileGridSize=(8, 8)`），有效拉伸暗部字迹与反光区域的反差，适应实验室不均匀台灯照射；
  - **6. 15px 边缘腐蚀采样与黑棋 L 亮度分位数判别算法 (15px Core Margin Erosion & L-Channel Luminance Ratio, `is_black_piece`)**：
    对检测边界框向内侵蚀 15 像素（`y1+15:y2-15, x1+15:x2-15`），剥离木质棋子边框与背景交叉线干扰；统计核心区域深黑墨色（ $L \lt 45$ ）像素数量占比：若占比超过 50%，则稳健判定为黑棋，完全免疫室内环境光的色温与偏色干扰；
  - **7. 棋盘视角与坐标极性自适应对齐算法 (Orientation Polarity Auto-Alignment, `set_black_view`)**：
    统计开局红/黑方棋子在画面中的平均 Y 坐标：若黑方在画面上方（远端），自动映射 Pt1 $\to$ a0；若黑方在画面下方（近端），自动映射 Pt3 $\to$ a0，实现棋盘顺逆摆放的 180° 自适应极性翻转，免除人工配置；
  - **8. 楚河汉界物理死区几何过滤算法 (Chu River Physical Deadzone Filtering)**：
    针对第 4 行与第 5 行之间的开阔印刷带，设立 $4.35 \lt y \lt 4.65$ 的归一化网格过滤死区，直接剔除落入该区域由“楚河汉界”篆刻书法字引起的伪检误检框；
  - **9. 双门槛置信度准入与迟滞跟踪门控 (Dual-Threshold Confidence Gate)**：
    设定新目标检测准入门槛 `detect_conf = 0.50` 与跟踪维持门槛 `keep_conf = 0.20`，构成施密特迟滞比较器特性，杜绝微弱噪点误触发，同时确保有效棋子在微弱阴影下持续稳定跟踪；
  - **10. 质心 EMA 指数移动平滑与 1.5px 距离死区滤波 (Centroid EMA Smoothing with 1.5px Deadzone)**：
    对目标质心执行 $\alpha = 0.28$ 的指数移动平均平滑，并附加 1.5 像素物理死区（ $\text{dist}^2 \gt 2.25\text{ px}^2$ ），彻底过滤相机传感器亚像素热噪与桌面微振动，保护伺服舵机；
  - **11. 瞬移跳变检测与走子迟滞消除算法 (Teleportation Bypass, `find2.txt`)**：
    当单帧目标位移平方 $\Delta d^2 \gt 2500\text{ px}^2$ 时，判定棋子正在被人类手部快速位移，算法立即旁路（Bypass）EMA 滤波直接置位最新物理坐标，彻底消除快速行棋时的视觉滞后与拖影；
  - **12. 全局动态运动门控机制 (Global Motion Gating)**：
    当全盘任意棋子位移 $\Delta d^2 \gt 25\text{ px}^2$ 时置位 `global_motion = True`，重置盘面稳定滑动窗口，严防走棋过程中抓取到中间不完整盘面；
  - **13. 棋子能量槽状态机与 12 帧历史众数投票 (Energy Tracking & 12-Frame Majority Voting)**：
    为每个跟踪 ID 维护动态能量槽（检出 +40，单帧丢失 -15，阈值 50），结合长度为 12 帧的历史逻辑坐标队列（`deque(maxlen=12)`），采用统计学众数投票（`Counter.most_common(1)`）锁定网格，消除偶发单帧跳变；
  - **14. 机械臂运动期视觉主动抑制与时序解耦 (Active Visual Suppression During Arm Manipulation, `suppress_detection`)**：
    机械臂进场抓放棋子时，调度器置位 `suppress_detection = True` 挂起视觉上报，防止机械臂连杆与其阴影被误判定为人类走棋；复位至待命点后再调用 `reset_baseline()` 强制刷新基准，实现感知与执行的完美时序解耦；
  - **15. 双重占有与 Track-ID 位移差分解算算法 (Dual Occupancy & Track-ID Displacement Differential, `main.py`)**：
    针对吃子动作引起的目标重叠与原位置腾空，算法联合判定 `pos not in current_board` 与 `last_stable_board[pos] != tid`，精准剥离唯一起点与终点；同时在调度器中内置 ID 粘连异常拦截与容错引导，防止程序崩溃；
  - **16. UI 交互层 2 倍无损几何坐标逆映射算法 (UI 2x Lossless Coordinate Mapping, `ui_main.py`)**：
    界面显示严格锁定为 640×360 像素（保持 1280×720 的标准 16:9 纵横比），交互标定点击事件直接乘 2 逆映射回原始传感器像素坐标，杜绝窗口缩放引起的标定点几何漂移。
- **吃子死锁难题与人机状态机**：
  - **未识汉字导致的吃子判定死锁**：因降维模型不识别具体兵种汉字、仅记录网格坐标，系统**根本不知道消失的棋子具体是哪一颗**。一旦发生吃子导致场上总数由 32 颗变为 31 颗，算法无法自动判定究竟是“棋子被吃离开棋盘”还是“人手走棋遮挡造成单帧漏检”，直接破坏了全盘棋子守恒的滑动窗口稳态判定；
  - **人机协同状态机妥协**：最终在 UI 界面引入**“玩家走棋确认按钮 / 键盘空格键”**机制。玩家走完棋并将手完全移开棋盘区域后，按下空格键置位 `force_detect_move = True`，系统在完全无手部遮挡与阴影的静止瞬间触发差分提取。该妥协确保了实机交付时 100% 动作可靠，但留下了**无法识别残局与任意局面**（必须从标准 32 颗全盘开局起步）以及**依赖人工按键（半自动）**的两大工程妥协。

#### 第四代升级 (Gen 4: 全局自研范式突破 —— 全局网格张量分类与自研训练流水线)

  为彻底攻克残局识别并摆脱按键依赖，在深入查阅前沿计算机视觉文献与姿态估计范式后，视觉系统全面重构并自主研发了第四代空间感知网络，建立了从物理数据采集到端到端张量推理的完整自研闭环：
- **第四代核心算法与端到端网络体系**：
  - **1. 物理单棋子微距切片与 Alpha 掩膜图元库构建**：
    对自制的红黑双方 32 枚导磁棋子（涵盖红黑 14 类兵种）逐一进行微距高清拍照与透明抠图（保留 Alpha 通道 Mask），构建高保真单棋子图元库；同时使用架设好的工业相机对 35 × 35 cm 米黄色棋盘拍摄纯净空盘正投影底图；
  - **2. 自动化棋盘图像合成引擎与真值张量生成器 (`CChessMixSinglePngCls`)**：
    自主研发全自动数据集渲染与标注流水线。将 32 枚单棋子图元进行随机轻微仿射变换、随机角度旋转（模拟人手随机摆放倾角）与 HSV 光影扰动，依据中国象棋排局规则或随机排布，将棋子自动镶嵌贴合到空盘的 90 个交叉点（A0 到 J8）上；在贴图渲染的同时，**程序自动生成完全对齐的 $10 \times 9 \times 16$ 空间真实标签张量（Ground Truth）**，零人工标注成本瞬间合成数万张涵盖各类中残局、不同光照与偏角的完美训练集；
  - **3. 基于 RTMPose-Tiny 的棋盘四角关键点姿态回归与透视标准化网络 (`cchess_pose`)**：
    采用基于高分辨率坐标分类（RTMCC）的轻量级姿态估计网络，直接输入原始斜视畸变画面，亚像素级回归预测棋盘物理 4 个角点（A0, A8, J0, J8），自动执行反透视投影展开，输出无畸变的标准正投影俯视图；
  - **4. 基于 Swin-Transformer V2 的层次化全局自注意力特征提取骨干 (`cchess_reg`)**：
    以标准正投影俯视图为输入，采用 Swin-Transformer V2 骨干网络，通过移位窗口自注意力机制捕捉全盘多尺度特征，建模全局棋盘拓扑与全盘棋子间的长距离上下文依赖；
  - **5. 空间网格聚合颈部网络 `Chess10_9Neck` 与多区域分类头 `CChessTableHead`**：
    专门构建几何重塑颈部网络将全局特征图映射聚合至 $10 \times 9$ 物理交叉网格，并由分类头输出 $10 \times 9 \times 16$ 空间分类张量，一次性完成全盘 90 个交叉点的 16 分类（红方 7 类、黑方 7 类、空位 `.`、杂物 `x`）；
  - **6. 组合损失函数监督 (`KLDiscretLoss` + `SmoothL1Loss`) 与整盘零错误（Full-err-zero）严苛评估体系**：
    采用离散 KL 散度与平滑 L1 联合损失监督训练，以整盘 90 格零错误率（Full-err-zero）作为严苛对弈指标；
  - **终极突破与闭环落地**：识别准确度极高、错误率极低，**彻底攻克残局与任意局面摆盘识别**；格子状态变更即刻捕获，**天然免疫吃子计数死锁**，完全免除人机确认按钮，真正实现了 100% 全自主感知闭环！

### 4.3 博弈决策与规则引擎模块 (张子琛负责)

博弈决策模块承担全盘局面解析、合法着法推演与最优走子评估任务，包含中国象棋规则约束求解器与深度卷积评估网络：

#### 1. 10×9 中国象棋完整规则约束求解器 (`game/board.py`)
严格实现中国象棋完整走棋规则，提供全局走法合法性判定、将死判定与动作推演：
- **直线障碍扫描算法（车/炮）**：
  通过 `is_path_clear` 沿行/列方向步进扫描中间交叉点：
  - **车（Ju）**：要求起点与终点同轴且路径内部障碍子计数 $N_{\text{obs}} = 0$；
  - **炮（Pao）**：不吃子时要求 $N_{\text{obs}} = 0$ 且目标格为空；吃子时严格要求**炮架计数 $N_{\text{obs}} = 1$** 且目标格存在敌方棋子；
- **马走日别马腿障碍检测算法 (`is_ma_valid`)**：
  位移满足 $|dx| \times |dy| = 2$。当横向跨越 $|dx|=2$ 时，检查横向中间拐弯点 $(y_1, \frac{x_1 + x_2}{2})$ 是否为空；当纵向跨越 $|dy|=2$ 时，检查纵向中间拐弯点 $(\frac{y_1 + y_2}{2}, x_1)$ 是否为空；
- **相/象走田塞象眼与楚河汉界不过河约束算法 (`is_xiang_valid`)**：
  位移严格满足 $|dx|=2, |dy|=2$。检测田字中心点 $(\frac{y_1 + y_2}{2}, \frac{x_1 + x_2}{2})$ 是否受阻（塞象眼）；并根据阵营施加边界不过河约束：红相限制在己方半场 $y_2 \ge 5$，黑象限制在己方半场 $y_2 \le 4$；
- **士/仕九宫斜行约束算法 (`is_shi_valid`)**：
  位移满足 $|dx|=1, |dy|=1$，且严格约束在九宫空间内部：红仕限定 $3 \le x_2 \le 5, 7 \le y_2 \le 9$；黑士限定 $3 \le x_2 \le 5, 0 \le y_2 \le 2$；
- **帅/将九宫正交与飞将对脸检测算法 (`is_jiang_valid`)**：
  单步移动约束在九宫内且 $|dx| + |dy| = 1$；同时内置红黑双将同列无障碍对脸规则（飞将杀）；
- **兵/卒过河前后单向/横行状态机算法 (`is_zu_valid`)**：
  - 红兵：未过河（ $y_1 \gt 4$ ）仅允许向前单步位移（ $dx=0, dy=-1$ ）；过河后（ $y_1 \le 4$ ）允许向前或左右横行（ $dy=-1$ 或 $dy=0, |dx|=1$ ），严禁后退；
  - 黑卒：未过河（ $y_1 \lt 5$ ）仅允许向前单步位移（ $dx=0, dy=1$ ）；过河后（ $y_1 \ge 5$ ）允许向前或左右横行（ $dy=1$ 或 $dy=0, |dx|=1$ ），严禁后退；
- **全盘合法走法生成算法 (`get_all_legal_moves`) 与走法历史推演栈**：
  遍历当前方全盘棋子，枚举全盘 90 格候选目标并经规则约束求解器过滤，输出全局合法动作集合，支撑 AI 决策与胜负判定。

#### 2. 14 通道空间二值特征张量提取器 (`get_state_tensor`)
将当前离散棋盘状态无损编码为三维特征张量 $\mathbf{S} \in \mathbb{R}^{14 \times 10 \times 9}$：
- 通道 0–6：分别对应黑方将、车、马、炮、象、士、卒的 One-Hot 二值分布；
- 通道 7–13：分别对应红方帅、车、马、炮、相、仕、兵的 One-Hot 二值分布；
每个交叉点有棋子处填入 $1.0$，空位填入 $0.0$，为深度卷积神经网络提供规整的空间拓扑输入。

#### 3. 深度卷积决策评估网络 `ChessNet` 与掩码策略 (`game/ai.py`)
- **网络架构设计**：
  - **卷积特征提取层**：包含三层连续二维卷积，通道维度逐级递增：
    - $\text{Conv1}: 14 \to 64$（Kernel $3 \times 3$, Padding 1, ReLU）
    - $\text{Conv2}: 64 \to 128$（Kernel $3 \times 3$, Padding 1, ReLU）
    - $\text{Conv3}: 128 \to 128$（Kernel $3 \times 3$, Padding 1, ReLU）
  - **全连接决策层**：展平为 $128 \times 10 \times 9 = 11520$ 维一维向量，经过两层多层感知机：
    - $\text{Linear1}: 11520 \to 1024$（ReLU）
    - $\text{Linear2}: 1024 \to 8100$（输出未归一化 Logits）
- **动作空间映射与掩码决策算法 (Action Masking)**：
  - 动作空间涵盖全盘 90 个交叉点间所有理论位移组合（ $90 \times 90 = 8100$ ）；走法索引映射关系为：
    $$\text{idx} = (y_1 \times 9 + x_1) \times 90 + (y_2 \times 9 + x_2)$$
  - **合法走法掩码过滤**：决策时仅在规则引擎生成的 `valid_moves` 候选集合内进行检索，选取 Logits 得分最高的动作：
    $$a^* = \arg\max_{m \in \mathcal{M}_{\text{valid}}} \text{Logits}[\text{idx}(m)]$$
    彻底杜绝模型输出走子规则违例动作；
- **高可用安全降级机制**：
  若工程目录未检测到预训练权重文件 `aaa.pth`，中枢决策引擎自动且平滑地降级为均匀随机策略（`random.choice(valid_moves)`），确保系统在模型缺失时仍能维持对弈闭环不崩溃。

#### 4. 下棋算法的未来优化方向
在工科展后续迭代中，决策算法将从现有的基础卷积评估全面升级为**强化学习（RL，自博弈训练）**，进一步提升中残局棋力与战术计算深度。

## 5. 硬件电气连接与总线定义

系统的物理硬件电气拓扑结构如下表所示：

| 硬件模组 | 物理接口 | 驱动协议 | 宿主控制引脚 | 电气特征与控制参数 |
| :--- | :--- | :--- | :--- | :--- |
| **PCA9685 舵机驱动板** | SDA / SCL | 硬件 I2C (100kHz 标准模式) | CH347 D0(SCL) / D1(SDA) | 16 通道 12 位分辨率，基准频率 50Hz ( $T = 20$ ms ) |
| **底座旋转舵机 (J1)** | PWM 通道 0 | 50Hz PWM 方波 | PCA9685 输出端 0 | RDS3235 金属数码舵机，水平方位角控制 |
| **大臂俯仰舵机 (J2)** | PWM 通道 4 | 50Hz PWM 方波 | PCA9685 输出端 4 | RDS3235 35kg·cm 高扭矩数码舵机，大臂抬升控制 |
| **小臂俯仰舵机 (J3)** | PWM 通道 8 | 50Hz PWM 方波 | PCA9685 输出端 8 | 20kg·cm 精密金属数码舵机，伸展半径与高度控制 |
| **腕部姿态舵机 (J4)** | PWM 通道 12 | 50Hz PWM 方波 | PCA9685 输出端 12 | 180° 金属舵机，强制保持末端吸盘垂直朝下 |
| **电磁铁继电器** | 控制信号 | CH347 原生 GPIO | CH347 GPIO2 (Pin 10 / DTR0) | 5V 继电器控制电磁铁通断，掩码 0x04 直接驱动 |
| **工业俯视摄像头** | USB 2.0 / UVC | DirectShow 协议 | PC USB 3.0 高速口 | 1280×720 @ 30 FPS，定焦低畸变镜头 |
| **WCH CH347 桥接器** | USB Type-C | 480Mbps 高速 USB | PC 宿主机 USB 口 | 硬件 USB 转 I2C/GPIO 工业桥接器 |

### PCA9685 12-Bit PWM 脉宽映射模型
PCA9685 分辨率为 12 位（4096 级计数值），在周期 $T = 20$ ms （50Hz）下，脉宽与寄存器 Tick 映射方程为：

$$
\text{Tick} = \left\lfloor \frac{T_{\text{pulse}}}{20\text{ ms}} \times 4096 \right\rfloor
$$

对于 RDS3235 舵机（角度 $\theta \in [0^\circ, 270^\circ]$ ，脉宽 0.5 ~ 2.5 ms ）：

$$
T_{\text{pulse}}(\theta) = 0.5\text{ ms} + \frac{\theta}{270^\circ} \times 2.0\text{ ms}
$$

$$
\text{Tick}(\theta) = \left\lfloor \frac{0.5 + \frac{\theta}{270} \times 2.0}{20} \times 4096 \right\rfloor = \left\lfloor 102.4 + \theta \times 1.517 \right\rfloor
$$

## 7. 快速复现与部署运行指南

### 7.1 环境依赖
- **操作系统**：Windows 10 / 11 (64-bit)
- **Python 环境**：Python 3.10+ (推荐使用 Anaconda 或 Miniconda)
- **CUDA 算力**：NVIDIA GPU (推荐 GTX 1650 / RTX 4060 及以上)
- **硬件依赖**：WCH CH347 驱动 (`CH347DLLA64.DLL`) 已内置于工程根目录

### 7.2 虚拟环境构建与依赖安装
```bash
# 1. 克隆代码仓库
git clone https://github.com/TJS-Git-Hub/ChessRobot.git
cd ChessRobot

# 2. 创建并激活 Python 3.10 隔离环境
conda create -n chess_robot python=3.10 -y
conda activate chess_robot

# 3. 安装依赖库与 PyTorch (CUDA 版本)
pip install -r requirements.txt
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu118
```

### 7.3 硬件自检与调优
```bash
# 1. 调试机械臂各轴舵机零位脉宽偏置 (基准 90° 竖直姿态)
python tools/calibrate_servo.py

# 2. 测试 WCH CH347 原生 GPIO2 继电器与电磁铁吸附动作
python tools/test_electromagnet.py

# 3. 校验机械臂作业半径与理论极限可达空间
python tools/calc_reach.py
```

### 7.4 启动对弈系统
- **启动 PyQt5 全功能交互控制台**：
  ```bash
  python ui_main.py
  ```
- **启动无界面终端 CLI 模式**：
  ```bash
  python main.py
  ```

## 8. 系统操作指南（对弈交互与标定）

1. **四点单应性交互标定与 ROI 锁定（含 UI $2\times$ 无损还原）**：
   - 启动系统后，在 PyQt5 控制台 $640 \times 360$ 视频画面中依次顺时针点击棋盘四个物理基准角点（1.左上 $\to$ 2.右上 $\to$ 3.右下 $\to$ 4.左下）；
   - UI 内部自动将点击坐标乘以 2 无损还原至 $1280 \times 720$ 物理分辨率并传递至算法层，通过 SVD 分解计算单应性矩阵 $\mathbf{H}$，并自动生成外扩 60px 的棋盘多边形掩膜（ROI Mask），彻底隔绝棋盘外弃子区的所有死子干扰。
2. **棋局摆放与对弈开始**：
   - 将红黑双方 32 枚自制导磁棋子摆放在米黄色棋盘标准初始位置；
   - 点击控制台界面的 `开始对弈`，系统自动锁定初始基准盘面。
3. **人类走棋与确认触发**：
   - 人类玩家执红先行走子；走子完毕并将手完全移开棋盘区域后，按下**键盘空格键**（或点击界面上的**走法确认**按钮）；
   - 视觉在静止无手部遮挡瞬间提取位移坐标并传递至 `move_queue`，算法大脑随即推算黑方最优应手。
4. **机械臂自动执行与视觉时序解耦**：
   - 机械臂执行期间，系统自动置位 `suppress_detection` 抑制视觉误报；机械臂从待命点出发，执行五阶段微距防刮蹭轨迹：巡航到达 $\to$ 8mm微距调平 $\to$ 垂直吸取 $\to$ 垂直微抬 $\to$ 巡航平移 $\to$ 目标点垂直下探落子（若吃子则先将敌子移送至外部弃子区） $\to$ 平滑复位至待命点并释放视觉抑制，恢复新一轮感知。
