## 1. システム概要とハードウェア治具製作

本システムは、高い可搬性と動作信頼性を両立させた実機対局プラットフォームであり、チームメンバーによりゼロから機構設計・組立・治具製作・プログラミングが行われました。

### 1.1 特製将棋盤と手作り磁気駒の製作詳細
- **特製将棋盤の物理選定と変遷**：
  - **初期版の淘汰（ $40 \times 40\,\text{cm}$ 濃緑色軟質盤）**：当初は $40 \times 40\,\text{cm}$ の濃緑色軟質盤を購入しましたが、4自由度ロボットアームとの実機結合テストにおいて、アームリンク長と作業空間境界（大臂 $L_2 = 231\,\text{mm}$、小臂 $L_3 = 231\,\text{mm}$）の物理的制約により、先端電磁石が**最遠端の第9列（赤方底線）の外側格子点に届かない（理論限界作業半径を超過）**ことが判明し、機構的干渉とストローク不足のため速やかに淘汰されました；
  - **定型量産版（ $35 \times 35\,\text{cm}$ ベージュ色軟質盤）**：外形寸法 $35 \times 35\,\text{cm}$ のベージュ色中国将棋用軟質携帯盤（ソフトマット）を特製再選定。格子間隔を約 $34.2\,\text{mm}$ に圧縮（制御ドライバ `config.py` 内の `SQUARE_WIDTH = 34.2`、`BOARD_ORIGIN_Y = 200.0` と厳密一致）することで、アームが盤上の全90個の交差点を安定かつスムーズに完全被覆できるようになりました。
- **完全手作りによる導磁性駒**：
  - 標準の太字「Microsoft YaHei」フォントを用いて、赤黒合計32枚の駒デザインを作成（直径 $3.0\,\text{cm}$ に厳密設定）；
  - 用紙に印刷後、手作業で1枚ずつ高精度に円形カット；
  - 直径 $3.0\,\text{cm}$ の薄型円形導磁金属プレートを購入し、表面に切り抜いた文字ラベルを密着貼り付けすることで、専用の磁気将棋駒を完成させました。
- **先端電磁石と把持方式**：
  - ロボットアーム先端に 5V DC 吸着用電磁石を搭載し、リレーモジュールにより通電・消磁を直接制御；
  - 吸着時はアームが駒直上へ垂直降下し、リレーがONとなり電磁石が駒の金属プレートを確実に吸着；
  - 目標格子点への到達後、リレーがOFFとなり消磁され、駒が安全に解放されます。

### 1.2 実測対局精度と性能指標
モーション制御の最重要課題は、**狭小空間での隣接駒との衝突回避**、および**目標交差点中心への確実な被覆（センタリングカバレッジ）**です。  
連続 20 手の実機対局テストにおいて：
- **18 回が交差点中心を完全に被覆**；
- **2 回が軽微なズレ**（把持・解放自体は正常）；
- **着手中心被覆率は 90% に到達**し、隣接する駒を倒すことなく安定した対局を達成しました。

## 4. システム構成とアルゴリズム変遷

システムは「**機構およびモーション制御**」「**視覚認識**」「**ゲーム推論・ルールエンジン**」の3大モジュールから構成されます。

---

### 4.1 機構およびモーション制御モジュール (担当: 田峻碩、調整補助: 劉超然)

ベース旋回（J1）、第1アーム（J2）、第2アーム（J3）、手首姿勢（J4）からなる4自由度関節型ロボットアームであり、先端電磁吸盤は常时垂直下向き（ $\phi = -90^\circ$ ）に拘束されます。

#### 1. 物理リンク幾何寸法 (`config.py`)
- ベース旋回中心高： $L_1 = 73.0\,	ext{mm}$
- 第1アーム長： $L_2 = 231.0\,	ext{mm}$
- 第2アーム長： $L_3 = 231.0\,	ext{mm}$
- 手首関節〜吸盤端長： $L_4 = 66.0\,	ext{mm}$

#### 2. 非線形フィードフォワード補償モデル (`kinematics.py`)
長アーム自重による弾性たわみと開ループサーボのバックラッシュを補償する制御則を導入：

**1. X 軸横方向幾何ゲイン補償**：

$$
X_{\text{comp}} = X \times K_x \quad (K_x = 1.125)
$$

**2. 合成作業半径・伸長補正**：

$$
R_{\text{target}} = \sqrt{X_{\text{comp}}^2 + Y^2}, \quad R_{\text{comp}} = R_{\text{target}} \times (1 - K_r) \quad (K_r = 0.06)
$$

**3. 自重たわみ高さフィードフォワード補償**：

$$
\text{comp}_z = Z + (R_{\text{target}} \times K_z) \quad (K_z = 0.12)
$$

#### 3. 幾何学的解析逆運動学（IK）の求解
手首垂直拘束のもと、空間3次元問題をピッチ平面へ幾何学的に分解して閉形式で求解：

**ステップ 1：ベース旋回角**（方位角 $\theta_1$ を求めてサーボ目標角 $t_1^{\text{deg}}$ へ換算）

$$
\theta_1 = \text{atan2}(X_{\text{comp}}, Y), \quad t_1^{\text{deg}} = \text{degrees}(\theta_1) + 90.0^\circ
$$

**ステップ 2：ピッチ高度差と弦長**

$$
\Delta Z = (\text{comp}_z + L_4) - L_1, \quad D = \sqrt{R_{\text{comp}}^2 + \Delta Z^2}
$$

**ステップ 3：余弦定理による関節内角の算出**

$$
\cos(\alpha) = \frac{L_2^2 + D^2 - L_3^2}{2 L_2 D}, \quad \cos(\gamma) = \frac{L_2^2 + L_3^2 - D^2}{2 L_2 L_3}
$$

**ステップ 4：各軸目標角の算出**

$$
\beta = \text{atan2}(\Delta Z, R_{\text{comp}})
$$

$$
t_2^{\text{deg}} = \text{degrees}(\beta + lpha), \quad t_3^{\text{deg}} = t_2^{\text{deg}} - (180.0^\circ - \text{degrees}(\gamma)), \quad t_4^{\text{relative}} = -90.0^\circ - t_3^{\text{deg}}
$$

#### 4. 微小空間5段階衝突回避ピック＆プレース軌道計画 (`control.py`)
密集配置された隣接駒への接触転倒を防ぐため、厳格な5段階ウェイポイント軌道を生成：
- **直上へ水平巡航**：安全巡航高度 $Z_{	ext{safe}} = 70.0\,	ext{mm}$ へ高速移動；
- **微小緩衝層への降下**：駒上面の 8mm 上空（ $Z_{	ext{micro}} = -25.0\,	ext{mm}$ ）で一時静止し手首姿勢を直立安定化；
- **垂直進入と電磁吸着**：低速で盤面 $Z_{	ext{board}} = -33.0\,	ext{mm}$ へ垂直降下し、リレーONで電磁石吸着（0.5秒保持）；
- **純垂直微小引き上げ**：前腕主導で純垂直に 8mm 引き上げ（ $Z_{	ext{micro}}$ へ復帰）、横揺れによる隣接駒の接触を完全に遮断；
- **巡航移動と目標着手**： $Z_{	ext{safe}}$ へ上昇後、目標位置直上へ水平移動し、同様の垂直微小進入により確実に駒を解放。

#### 5. モーション制御の今後の改良計画
今後は多軸補間プロファイルに S 字加減速フィルタを組み込み、長距離移動時のメカニカルな振動を極小化する予定です。

### 4.2 視覚認識モジュールと4世代の進化 (単独担当: 劉超然)

データセットの全数収集・アノテーションから認識アルゴリズム開発まで、劉超然が単独で主導しました。4世代にわたる試行錯誤の歴史は以下の通りです：

#### 第1世代プロトタイプ (Gen 1: ハフ円検出 ＋ 合成文字 OCR 探索)
- **着想**：OpenCV ハフ円変換（Hough Circles）で駒の円形輪郭と中心座標を特定；スクリプトにより白地に赤黒太字の Microsoft YaHei フォント画像を1,000枚以上自動生成し、軽量 CNN による2段階文字 OCR を試行。
- **2回にわたる内部試行錯誤と限界分析**：
  - **サブ世代 1（CNN による色・文字同時認識）**：当初は単一の CNN モデルで紅黒陣営分類と漢字文字分類の同時出力を試みたが、複雑な環境光やレンズ歪みの下では紅黒の色彩特徴分離度が極めて低く、モデルが安定収束せず失敗；
  - **サブ世代 2（HSV 色空間分離 ＋ CNN 単独文字認識）**：タスクを分離し、陣営分類を HSV 色空間へ委譲（HSV による陣営分類は実測で良好に機能）、CNN は漢字認識に特化。
- **完全破棄に至った客観的根因**：
  - **文字認識の完全破綻**：訓練データがPC生成の Microsoft YaHei 理想フォントに100%依存し、**実写画像サンプルが皆無**であったため、汎化性能が極めて脆弱；
  - **遠方小スケールの激しい歪み**：盤面全体を捉えるためカメラを比較的高位置に架設せざるを得ず、ハフ円で切り出した駒パッチの解像度が極めて低くなり、漢字の筆画が潰れて完全に識別不能；
  - **検出感度調整の破綻**：ハフ円が環境反射光に極めて敏感で、感度を下げれば暗部で見落とし、上げれば反射スポットが偽円だらけに。実機アームとの結合テストに至る前段階の純粋な視覚ベンチ検証において、認識率の低さから速やかに廃案としました。

#### 第2世代進化 (Gen 2: YOLOv11 による14クラス細粒度物体検出)
- **着想と俯瞰定点データ収集**：
  幾何オペレータから深層学習へ移行。産業用カメラをシステム底座の専用金属アーム上に固定（高さ約 $40\,\text{cm}$、`collect_real_data.py`）、一定の俯瞰角で様々な照度、角度、空盤、対局中盤、部分遮蔽を含む620枚の実写画像を撮影；**Roboflow** 上で14クラスの駒を1枚ずつ手作業で矩形アノテーション（1盤面あたり32駒）；ローカルの **RTX 4060** で YOLOv11n をファインチューニング（70% 訓練、20% 検証、10% テスト）。
- **極限データ拡張パイプライン（Data Augmentation）**：
  室内光の乱反射を克服しロバスト性を極限まで高めるため、学習スクリプト（`train.py`）内に高度なデータ拡張パイプラインを構築：
  - **幾何・空間アフィン変換**： $\pm 45^\circ$ の盤面回転（`degrees=45.0`）、 $\pm 15\%$ の空間平行移動、 $\pm 60\%$ の多倍率スケーリング、 $\pm 15^\circ$ の剪断歪み、および水平/垂直反転（`fliplr/flipud=0.5`）；
  - **遮蔽・合成拡張**：Mosaic タイリング（1.0）、MixUp（0.2）、人の手の影や反射スポットを模擬するランダム消去（Random Erasing、`erasing=0.4`）、Copy-Paste（0.2）；
  - **測光・色彩変動**：HSV 彩度（0.5）および明度（0.4）のランダム摂動を与え、不均一な照明変動を抑制。
- **実戦結果と盤面変更に伴うドメインシフト痛点（Domain Shift）**：
  - **物体位置検出の飛躍的向上**：駒の検出率と中心座標精度は劇的に向上し、ハフ円の見落としや偽円問題は完全に解消；
  - **盤面変更による深刻なドメインシフト（Domain Shift）**：収集した620枚のデータセットのうち、**約500枚は初期に淘汰された濃緑色盤上で撮影・アノテーションされたもの**でした。ベージュ色盤に変更後は納期制約から120枚の追加撮影に留まり、下地色の激変（濃緑 vs 薄ベージュ）による強烈な色彩ドメインシフトが発生、定型盤面上でのモデル汎化性能が大きく損なわれました；
  - **文字分類誤り率が高止まりした物理的根因**：**この段階ではまだ盤面の正投影補正（ホモグラフィ透視展開歪み補正）を導入していなかった**。斜め俯瞰による遠方小スケール文字の筆画が透視幾何圧縮によって激しく潰れ、酷似した漢字（**「車」と「卒」、「馬」と「兵」**）の混同が極めて深刻で、一部の特徴的な文字のみしか正しく識別できなかった。1文字の誤りも許されない対局システムにおいて、本モデルの直接投入は不可能と判断。

#### 第3世代実戦システム (Gen 3: 戦略的工学的次元削減 —— YOLO位置検出 ＋ 紅黒2値分類)
- **工学的引き算と正の成果**：
  - 納期と未展開フォント識別の物理的限界を直視し英断：14クラスの細微文字認識を断念し、YOLO のタスクを**「駒の位置検出 ＋ 紅黒2値陣営分類」**へ大胆に次元削減；
  - データセットは「紅」「黒」の2クラスのみで良く、学習は急速に収束。**実機対局における位置検出と紅黒分類の精度は極めて高く、誤認識率は極小化を達成**；
  - ホモグラフィ透視変換（Homography）と組み合わせ、中心点を盤面 10×9 物理グリッドへリアルタイム写像し、移動前後の座標差分（例: `e6 -> e4`）のみを思考エンジンへ伝達。
- **自研中核視覚アルゴリズム行列（九大基盤工学実装メカニズム）**：
  - **1. 時計回り4点ホモグラフィ標定と 60px ROI マスク遮断（外部棄子エリアの完全隔離）**：
    起動時に時計回りで盤の4隅（左上 $\to$ 右上 $\to$ 右下 $\to$ 左下）をクリックし、SVD 分解により透視ホモグラフィ行列 $\mathbf{H}$ を算出。外側 60px のマージン（`roi_buffer_px = 60`、約 2-3cm）による凸多角形頂点を自動生成し、`cv2.fillPoly` と `cv2.bitwise_and` により二値マスク（Mask）を生成、**盤面関心領域（ROI）外の全背景を強制ゼロマスク化**。ロボットアームが駒取り後に盤面右側の外部棄子エリア（Graveyard）へ死駒を移送した際、**盤外の全死駒が ROI マスクによって完全に遮断され、盤外駒によるゴースト誤検出を 100% 根絶**；
  - **2. MOG2 混合ガウス背景差分——物理層動的手部遮蔽検知**：
    `find_chess.py` において `cv2.createBackgroundSubtractorMOG2(history=500, varThreshold=120, detectShadows=True)` を導入。画像を $640 \times 360$ にダウンサンプリングして高速処理し、運動前景マスクと盤面 ROI の交差領域を抽出。`cv2.findContours` で前景最大輪郭面積を算出し、2,000 ピクセルを超えた場合に人間の手が盤面に進入したと判定、即座に `is_occluded = True` をセットして物理層遮蔽アラートを発報し盤面更新をロック；
  - **3. 非同期シングルバッファゼロ遅延映像ストリームエンジン（`VideoStream`）**：
    OpenCV の動画取り込みを独立デーモンスレッド化し、ドライババッファサイズを強制的に 1（`CAP_PROP_BUFFERSIZE = 1`）に固定。マルチスレッド処理時のフレーム滞留と遅延を根絶し、推論のたびに常に即時 0 遅延の最新 720p 映像を供給；
  - **4. LAB 色空間 CLAHE 適応型ヒストグラム平坦化前処理**：
    推論前に LAB 色空間へ変換し、L 輝度チャンネルにコントラスト制限適応型ヒストグラム平坦化（`cv2.createCLAHE(clipLimit=3.5, tileGridSize=(8, 8))`）を適用。暗部の字画と光の反射コントラストを局所強調し、実験室の不均一な照明変動に適応；
  - **5. LAB 空間 L 輝度比に基づく高純度黒駒陣営判別（`is_black_piece`）**：
    室内照明の複雑な色温度変動による誤認を防ぐため、駒内部の円形領域を切り出して LAB 空間の L チャンネルを解析。 $L < 45$ （漆黒の墨色特徴）の画素割合が 50% を超える場合に黒駒と堅牢判定し、環境光の色相ドリフトを完全克服；
  - **6. 楚河漢界物理デッドゾーンフィルタ（Ghost Detection Filter）**：
    第4行と第5行の間の開闊地帯に対し、 $4.35 < y < 4.65$ の物理除外ゾーンを設定し、盤面に印刷された装飾毛筆文字の誤検知枠を即時排除；
  - **7. 二重閾値信頼度と EMA 質心平滑化防振（Anti-Jitter Filtering）**：
    新規検出閾値 `detect_conf = 0.50` と追跡維持閾値 `keep_conf = 0.20` を分離し、 $\alpha = 0.28$ の指数移動平均（EMA）と 1.5 ピクセル不感帯（`dist_sq > 2.25`）を組み合わせ、ピクセル微小振動によるサーボの不要なジッターを完全解消；
  - **8. 駒エネルギートラッキングと 12 フレーム履歴多数決フィルタ（Majority Voting）**：
    追跡 ID ごとにエネルギー状態マシン（検出時 +40、単一フレーム見失い時 -15、有効閾値 50）を管理し、長さ 12 フレームの履歴デック（`deque(maxlen=12)`）と統計学的多数決（`Counter.most_common(1)`）により物理格子を確定、偶発的な座標跳躍を完全排除；
  - **9. アーム動作時の能動的視覚抑制と時間的デカップリング（`suppress_detection`）**：
    ロボットアームが盤面上で駒の吸着・着手を行う間、メイン制御プログラムが `suppress_detection = True` をセットして視覚報告を一時停止。金属アームおよびその影が着手として誤検知されるのを防止し、待機位置復帰後に `reset_baseline()` で基準盤面を更新、知覚と動作の完璧な時間的デカップリングを達成。
- **「文字未認識」に起因する駒取り判定デッドロックと人機協調**：
  - **文字未識別による駒取り判定の死滅**：次元削減モデルは具体的な兵種文字を識別せず座標占有のみを記録するため、**どの駒が消失したのかシステムには判別不能**。駒取りにより盤上の総駒数が 32 個から 31 個に減少した際、アルゴリズムは「駒が正しく取られて盤外に出た」のか「人の手による遮蔽で一時的に見失った」のかを自動判別できず、全駒数保存を前提とするスライディングウィンドウ安定判定が破綻；
  - **人機協調ステートマシン**：最終的に UI 上に**「プレイヤー着手確認ボタン / スペースキー」**機構を導入。人間プレイヤーが着手を終えて手を完全に引いた後、スペースキーを押すことで `force_detect_move = True` がセットされ、手の影がない完全静止の瞬間に差分抽出を実行。この妥協により実機デモで 100% の動作信頼性を勝ち取ったものの、**残局に対応できない（標準32駒開局からのみ開始可能）**点と、**手動キー入力に依存する（半自動）**という2大妥協が残存。

## 5. ハードウェア電気接続とバス定義

物理ハードウェアの電気的接続構成は以下の通りです：

| モジュール | 物理ポート | 通信規約 | 接続先 | 制御パラメータ |
| :--- | :--- | :--- | :--- | :--- |
| **PCA9685 サーボドライバ** | SDA / SCL | ハードウェア I2C (100kHz 標準) | CH347 D0(SCL) / D1(SDA) | 16ch 12ビット PWM、50Hz ( $T = 20\,\text{ms}$ ) |
| **ベース旋回 (J1)** | PWM ch0 | 50Hz PWM | PCA9685 出力0 | RDS3235 金属サーボ、水平方位角 |
| **第1アーム (J2)** | PWM ch4 | 50Hz PWM | PCA9685 出力4 | RDS3235 35kg·cm 高トルクサーボ、リフト |
| **第2アーム (J3)** | PWM ch8 | 50Hz PWM | PCA9685 出力8 | 20kg·cm デジタルサーボ、前後半径 |
| **手首関節 (J4)** | PWM ch12 | 50Hz PWM | PCA9685 出力12 | 180° 金属サーボ、吸盤垂直保持 |
| **電磁石リレー** | 制御信号 | CH347 ネイティブ GPIO | CH347 GPIO2 (ピン10 / DTR0) | 5V リレー駆動、マスク 0x04 直接通断 |
| **俯瞰産業カメラ** | USB 2.0 / UVC | DirectShow | PC USB 3.0 | 1280×720 @ 30 FPS、低歪みレンズ |
| **WCH CH347 ブリッジ** | USB Type-C | 480Mbps 高速 USB | PC USB | 高速 USB-I2C/GPIO 工業ブリッジ |

### PCA9685 12-Bit PWM 変換モデル
周波数 50Hz（周期 $T = 20\,\text{ms}$）、12ビット分解能（4096段階）におけるレジスタ Tick 算出式：

$$
\text{Tick} = \left\lfloor \frac{T_{\text{pulse}}(\text{ms})}{20\,\text{ms}} \times 4096 \right\rfloor
$$

RDS3235 サーボ（ $\theta \in [0^\circ, 270^\circ]$ 、パルス幅 $0.5 \sim 2.5\,\text{ms}$ ）：

$$
T_{\text{pulse}}(\theta) = 0.5\,\text{ms} + \frac{\theta}{270^\circ} \times 2.0\,\text{ms}
$$

$$
\text{Tick}(\theta) = \left\lfloor \frac{0.5 + \frac{\theta}{270} \times 2.0}{20} \times 4096 \right\rfloor = \left\lfloor 102.4 + \theta \times 1.517 \right\rfloor
$$

## 7. クイックスタートと環境構築ガイド

### 7.1 動作要件
- **OS**：Windows 10 / 11 (64-bit)
- **Python**：Python 3.10+ (Anaconda / Miniconda 推奨)
- **GPU**：NVIDIA GPU (GTX 1650 / RTX 4060 以上推奨)
- **ドライバ**：WCH CH347 ドライバ (`CH347DLLA64.DLL`) をルートに同梱済み

### 7.2 仮想環境構築と依存パッケージの導入
```bash
# 1. リポジトリのクローン
git clone https://github.com/TJS-Git-Hub/ChessRobot.git
cd ChessRobot

# 2. Python 3.10 仮想環境の作成と有効化
conda create -n chess_robot python=3.10 -y
conda activate chess_robot

# 3. 依存ライブラリおよび CUDA 版 PyTorch のインストール
pip install -r requirements.txt
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu118
```

### 7.3 ハードウェア接続と個別診断
```bash
# 1. 各軸サーボの零点パルス幅校正（直立90°基準姿勢）
python tools/calibrate_servo.py

# 2. WCH CH347 ネイティブ GPIO2 リレーおよび電磁石吸着テスト
python tools/test_electromagnet.py

# 3. アーム作業限界半径および理論可達空間の検証
python tools/calc_reach.py
```

### 7.4 対局システムの起動
- **PyQt5 GUI ダッシュボードの起動**：
  ```bash
  python ui_main.py
  ```
- **CLI ターミナル対局モードの起動**：
  ```bash
  python main.py
  ```

## 8. システム操作手順（キャリブレーションと対局）

1. **4点ホモグラフィ対話型キャリブレーションと ROI 固定（UI $2\times$ 座標無損マッピング内蔵）**：
   - 起動後、PyQt5 操作画面の $640 \times 360$ 映像表示上で将棋盤の4隅を時計回り（1.左上 $\to$ 2.右上 $\to$ 3.右下 $\to$ 4.左下）に順次クリック；
   - UI 内部でクリック座標を自動的に 2 倍して $1280 \times 720$ の物理解像度へ無損復元し、SVD 分解によりホモグラフィ行列 $\mathbf{H}$ を算出、外側 60px を含めた盤面多角形マスク（ROI Mask）を自動生成して盤外の棄子エリアにある全死駒の干渉を完全に遮断します。
2. **初期配置と対局開始**：
   - 32 枚の手作り磁気駒をベージュ色の軟質盤の標準初期位置に並べます；
   - 画面の `対局開始`（Start Match）をクリックし基準初期盤面をロックします。
3. **人間プレイヤーの着手と協調トリガー**：
   - 人間（赤番）が駒を動かし、盤上から手を完全に引いた後、**スペースキー**（または画面上の**着手確定ボタン**）を押します；
   - 手の影がない静止画面から変位座標を瞬時に抽出して `move_queue` へ投入し、思考エンジンが応手を決定します。
4. **ロボットアームの自動着手実行と視覚の時間的デカップリング**：
   - アーム動作中、システムは自動的に `suppress_detection` をセットして視覚誤検知を抑制；アームが待機位置を出撃し、5段階微小空間軌道（巡航進入 $\to$ 8mm微小姿勢安定 $\to$ 垂直吸着 $\to$ 垂直微小引き上げ $\to$ 巡航移送 $\to$ 目標点垂直着手（駒取り時は先に敵駒を外部棄子エリアへ移送） $\to$ 待機復帰）を実行し、待機位置への復帰とともに視覚抑制を解除して新たな知覚サイクルを再開します。
