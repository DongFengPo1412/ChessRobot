## 1. システム概要とハードウェア治具製作

本システムは、高い可搬性と動作信頼性を両立させた実機対局プラットフォームであり、チームメンバーによりゼロから機構設計・組立・治具製作・プログラミングが行われました。

### 1.1 特製将棋盤と手作り磁気駒の製作詳細
- **特製将棋盤**：外形寸法 $35 \times 35\,\text{cm}$ のベージュ色中国将棋用硬質ボードを採用。明確な格子線と低反射マット処理が施されています。
- **完全手作りによる導磁性駒**：
  - 標準の太字「Microsoft YaHei」フォントを用いて、赤黒合計32枚の駒デザインを作成（直径 $3.0\,\text{cm}$ に厳密設定）；
  - 用紙に印刷後、手作業で1枚ずつ高精度に円形カット；
  - 直径 $3.0\,\text{cm}$ の薄型円形導磁金属プレートを購入し、表面に切り抜いた文字ラベルを密着貼り付けすることで、専用の磁気将棋駒を完成させました。
- **先端電磁石と把持方式**：
  - ロボットアーム先端に 5V DC 吸着用電磁石を搭載し、リレーモジュールにより通電・消磁を直接制御；
  - 吸着時はアームが駒直上へ垂直降下し、リレーがONとなり電磁石が駒の金属プレートを確実に吸着；
  - 目標格子点への到達後、リレーがOFFとなり消磁され、駒が安全に解放されます。

### 1.2 実測対局精度と性能指標
モーション制御の最重要課題は、**狭小空間での隣接駒との衝突回避**、および**目標交差点中心への確実な被覆（センタリングカバレッジ）**です。  
連続 20 手の実機対局テストにおいて：
- **18 回が交差点中心を完全に被覆**；
- **2 回が軽微なズレ**（把持・解放自体は正常）；
- **着手中心被覆率は 90% に到達**し、隣接する駒を倒すことなく安定した対局を達成しました。

## 4. システム構成とアルゴリズム変遷

システムは「**機構およびモーション制御**」「**視覚認識**」「**ゲーム推論・ルールエンジン**」の3大モジュールから構成されます。

---

### 4.1 機構およびモーション制御モジュール (担当: 田峻碩、調整補助: 劉超然)

ベース旋回（J1）、第1アーム（J2）、第2アーム（J3）、手首姿勢（J4）からなる4自由度関節型ロボットアームであり、先端電磁吸盤は常時垂直下向き（$\phi = -90^\circ$）に拘束されます。

#### 1. 物理リンク幾何寸法 (`config.py`)
- ベース旋回中心高：$L_1 = 73.0\,\text{mm}$
- 第1アーム長：$L_2 = 231.0\,\text{mm}$
- 第2アーム長：$L_3 = 231.0\,\text{mm}$
- 手首関節〜吸盤端長：$L_4 = 66.0\,\text{mm}$

#### 2. 非線形フィードフォワード補償モデル (`kinematics.py`)
長アーム自重による弾性たわみと開ループサーボのバックラッシュを補償する制御則を導入：
- **X 軸横方向幾何ゲイン補償**：$X_{\text{comp}} = X \times K_x \quad (K_x = 1.125)$
- **合成作業半径・伸長補正**：$R_{\text{target}} = \sqrt{X_{\text{comp}}^2 + Y^2}$、$R_{\text{comp}} = R_{\text{target}} \times (1 - K_r) \quad (K_r = 0.06)$
- **自重たわみ高さフィードフォワード補償**：$\text{comp}_z = Z + (R_{\text{target}} \times K_z) \quad (K_z = 0.12)$

#### 3. 幾何学的解析逆運動学（IK）の求解
手首垂直拘束のもと、空間3次元問題をピッチ平面へ幾何学的に分解して閉形式で求解：
1. **ベース旋回角**：$\theta_1 = \operatorname{atan2}(X_{\text{comp}}, Y)$、サーボ角へ換算 $t_1^{\text{deg}} = \operatorname{degrees}(\theta_1) + 90.0^\circ$；
2. **ピッチ高度差と弦長**：$\Delta Z = (\text{comp}_z + L_4) - L_1$、$D = \sqrt{R_{\text{comp}}^2 + \Delta Z^2}$；
3. **余弦定理による関節内角の算出**：

$$
\cos(\alpha) = \frac{L_2^2 + D^2 - L_3^2}{2 L_2 D}, \quad \cos(\gamma) = \frac{L_2^2 + L_3^2 - D^2}{2 L_2 L_3}
$$

4. **各軸目標角の算出**：$\beta = \operatorname{atan2}(\Delta Z, R_{\text{comp}})$、第1アーム角 $t_2^{\text{deg}} = \operatorname{degrees}(\beta + \alpha)$、第2アーム角 $t_3^{\text{deg}} = t_2^{\text{deg}} - (180.0^\circ - \operatorname{degrees}(\gamma))$、手首相対角 $t_4^{\text{relative}} = -90.0^\circ - t_3^{\text{deg}}$。

#### 4. 微小空間5段階衝突回避ピック＆プレース軌道計画 (`control.py`)
密集配置された隣接駒への接触転倒を防ぐため、厳格な5段階ウェイポイント軌道を生成：
- **直上へ水平巡航**：安全巡航高度 $Z_{\text{safe}} = 70.0\,\text{mm}$ へ高速移動；
- **微小緩衝層への降下**：駒上面の 8mm 上空（$Z_{\text{micro}} = -25.0\,\text{mm}$）で一時静止し手首姿勢を直立安定化；
- **垂直進入と電磁吸着**：低速で盤面 $Z_{\text{board}} = -33.0\,\text{mm}$ へ垂直降下し、リレーONで電磁石吸着（0.5秒保持）；
- **純垂直微小引き上げ**：前腕主導で純垂直に 8mm 引き上げ（$Z_{\text{micro}}$ へ復帰）、横揺れによる隣接駒の接触を完全に遮断；
- **巡航移動と目標着手**：$Z_{\text{safe}}$ へ上昇後、目標位置直上へ水平移動し、同様の垂直微小進入により確実に駒を解放。

#### 5. モーション制御の今後の改良計画
今後は多軸補間プロファイルに S 字加減速フィルタを組み込み、長距離移動時のメカニカルな振動を極小化する予定です。

### 4.2 視覚認識モジュールと4世代の進化 (単独担当: 劉超然)

データセットの全数収集・アノテーションから認識アルゴリズム開発まで、劉超然が単独で主導しました。4世代にわたる試行錯誤の歴史は以下の通りです：

#### 第1世代プロトタイプ (Gen 1: ハフ円検出 ＋ 合成文字 OCR)
- **着想**：OpenCV ハフ円変換（Hough Circles）で駒の円形輪郭と中心座標を特定；Microsoft YaHei フォントを用いて白地に赤黒太字の合成データセット（1,000枚以上）を自動生成し、軽量 CNN で文字 OCR を試行。
- **課題と限界**：
  - **照明変動への極端な脆弱性**：室内光やデスクライトの反射によりハフ円パラメータの調整が極めて困難化。感度を下げると暗い駒を完全に見落とし、感度を上げると光の反射スポットを全て円として誤検出し画面が偽円だらけに；
  - **位置ズレによる把持ミス**：アクリル盤の乱反射により中心位置が $5\,\text{mm}$ 以上ずれ、吸着ミスが多発したため第1世代は断念。

#### 第2世代プロトタイプ (Gen 2: YOLOv11 による14クラス直接検出)
- **着想**：幾何オペレータから深層学習へ移行。様々な照度、角度、配置、遮蔽を含む620枚の実写画像を撮影；**Roboflow** 上で14クラスの駒を1枚ずつ手作業で矩形アノテーション；ローカルの **RTX 4060** で YOLOv11n をファインチューニング（70% 訓練、20% 検証、10% テスト）。
- **課題と限界**：
  - 物体検出率は飛躍的に向上し、ハフ円の誤検出問題は解消；
  - **透視歪みによる文字混同**：広角レンズ周辺部での幾何学的圧縮により、遠方の小さな文字細部が潰れ、酷似した文字（**「車」と「卒」、「馬」と「兵」**）の混同が多発。将棋対局では1文字の誤認識が致命的となるため、対局エンジンが破綻。

#### 第3世代本番システム (Gen 3: 戦略的工学的妥協 —— YOLO位置検出 ＋ 紅黒2値分類)
- **タスクの戦略的次元削減**：
  - 納期と物理的文字識別の限界を直視し、英断を下す：14クラスの微細な文字分類を断念し、YOLO のタスクを**「駒の位置検出 ＋ 紅黒2値陣営分類」**へ大胆に次元削減；
  - YOLO は駒の中心位置と陣営のみを安定出力し、ホモグラフィ透視変換を介して物理グリッドへ写像。視覚モジュールは移動前後の変化座標（例: `e6 -> e4`）のみを思考エンジンへ伝達。
- **駒取り時のデッドロックと半自動協調の妥協**：
  - **全駒数32個のカウント破綻**：当初は盤上の全32個の駒数をスライディングウィンドウの安定判定基準としていたため、駒取りが発生して31個に減ると「駒が取られた」のか「人の手で遮蔽されている」のか区別がつかず、システムがデッドロックに陥る問題が発生；
  - **人機協調ステートマシン**：最終的に**「着手確定ボタン / スペースキー」**を導入。人間プレイヤーが着手を終えて手を引いた後、確定ボタンを押すことで `force_detect_move = True` がセットされ、手の影がない瞬間を確実に比較。この妥協により本番デモで100%の動作安定性を勝ち取ったものの、**残局（途中局面）に対応できない（標準初期配置からのみ開始可能）**点と、**ボタン押しが必要な半自動運用である**という2大課題が残存。

#### 第4世代SOTAアップグレード (Gen 4: 工科展リブート全面再構築 —— 大域グリッドテンソル分類)
- **明日より再始動する最新アーキテクチャ**：
  大学工科展への出展に向けて、オープンソース SOTA パラダイム（[Chinese-Chess-Recognition](https://github.com/TheOne1006/chinese-chess-recognition) に基づく）を全面導入し再構築：
  - **4隅キーポイント自動補正**：OpenMMLab MMPose 姿勢推定モデルにより盤面の4隅を全自動検出し、手動クリックなしに標準俯瞰図へ自動透視変換；
  - **Swin-Transformer 2 特徴テンソル出力**：局所バウンディングボックスの概念を完全撤廃；Swin-Transformer 2 が直接 $10 \times 9 \times 16$ の空間テンソルを出力し、盤上90個の全交差点に対して一括16分類（空位 / その他 / 紅黒14駒）を実行；
  - **究極のブレークスルー**：**残局や任意の途中配置盤面を瞬時に完全認識可能**；格子の状態変化を直接捉えるため**駒取り時のカウント死に完全に耐性**を持ち、人間による確認ボタンを完全撤廃した、真の100%全自動クローズドループを実現！

### 4.3 ゲーム推論およびルールエンジンモジュール (担当: 張子琛)

#### 1. ルールエンジンと合法手生成 (`game/board.py`)
10x9 中国将棋ルールを完全実装（車・砲の直線移動、馬の足止め、象の目塞ぎ、士・将の九宮拘束）し、合法手判定と履歴ロールバック機構を内蔵。

#### 2. 深層学習評価・着手決定ネットワーク (`game/ai.py`)
- PyTorch により3層畳み込みと2層全結合からなる `ChessNet` を構成；
- $14 \times 10 \times 9$ の空間テンソルを入力とし、8100次元のアクションスコアを出力；
- 合法手マスク処理により最高スコアの合法手を選択。モデル重み `aaa.pth` が未配置の場合は、候補となる合法手からランダム選択へ安全に降格し動作を継続。

#### 3. 将棋アルゴリズムの今後の改良計画
工科展に向けて、現在の基本畳み込みモデルから**強化学習（RL、自己対戦学習）**へと全面刷新し、中盤および終盤での戦術計算深度を飛躍的に高める予定です。

## 5. ハードウェア電気接続とバス定義

物理ハードウェアの電気的接続構成は以下の通りです：

| モジュール | 物理ポート | 通信規約 | 接続先 | 制御パラメータ |
| :--- | :--- | :--- | :--- | :--- |
| **PCA9685 サーボドライバ** | SDA / SCL | ハードウェア I2C (100kHz 標準) | CH347 D0(SCL) / D1(SDA) | 16ch 12ビット PWM、50Hz ($T = 20\,\text{ms}$) |
| **ベース旋回 (J1)** | PWM ch0 | 50Hz PWM | PCA9685 出力0 | RDS3235 金属サーボ、水平方位角 |
| **第1アーム (J2)** | PWM ch4 | 50Hz PWM | PCA9685 出力4 | RDS3235 35kg·cm 高トルクサーボ、リフト |
| **第2アーム (J3)** | PWM ch8 | 50Hz PWM | PCA9685 出力8 | 20kg·cm デジタルサーボ、前後半径 |
| **手首関節 (J4)** | PWM ch12 | 50Hz PWM | PCA9685 出力12 | 180° 金属サーボ、吸盤垂直保持 |
| **電磁石リレー** | 制御信号 | CH347 ネイティブ GPIO | CH347 GPIO2 (ピン10 / DTR0) | 5V リレー駆動、マスク 0x04 直接通断 |
| **俯瞰産業カメラ** | USB 2.0 / UVC | DirectShow | PC USB 3.0 | 1280×720 @ 30 FPS、低歪みレンズ |
| **WCH CH347 ブリッジ** | USB Type-C | 480Mbps 高速 USB | PC USB | 高速 USB-I2C/GPIO 工業ブリッジ |

### PCA9685 12-Bit PWM 変換モデル
周波数 50Hz（周期 $T = 20\,\text{ms}$）、12ビット分解能（4096段階）におけるレジスタ Tick 算出式：

$$
\text{Tick} = \left\lfloor \frac{T_{\text{pulse}}(\text{ms})}{20\,\text{ms}} \times 4096 \right\rfloor
$$

RDS3235 サーボ（$\theta \in [0^\circ, 270^\circ]$、パルス幅 $0.5 \sim 2.5\,\text{ms}$）：

$$
T_{\text{pulse}}(\theta) = 0.5\,\text{ms} + \frac{\theta}{270^\circ} \times 2.0\,\text{ms}
$$

$$
\text{Tick}(\theta) = \left\lfloor \frac{0.5 + \frac{\theta}{270} \times 2.0}{20} \times 4096 \right\rfloor = \left\lfloor 102.4 + \theta \times 1.517 \right\rfloor
$$

## 8. システム操作手順（キャリブレーションと対局）

1. **4点ホモグラフィ対話型キャリブレーション**：
   - 起動後、映像ウィンドウ上で将棋盤の4隅を時計回り（1.左上 $\to$ 2.右上 $\to$ 3.右下 $\to$ 4.左下）に順次クリック；
   - SVD 分解によりホモグラフィ行列 $\mathbf{H}$ が算出され、歪みのない物理ミリメートル座標へ正確に写像されます。
2. **初期配置と対局開始**：
   - 32 枚の手作り磁気駒をベージュ色の将棋盤の標準初期位置に並べます；
   - 画面の `対局開始`（Start Match）をクリックし盤面をロックします。
3. **人間プレイヤーの着手と協調トリガー**：
   - 人間（赤番）が駒を動かし、盤上から手を引いた後、**スペースキー**（または画面上の**着手確定ボタン**）を押します；
   - 視覚モジュールが変位を検知して `move_queue` へ投入し、思考エンジンが応手を決定します。
4. **ロボットアームの着手実行**：
   - アームが待機位置を出撃し、5段階微小空間軌道（巡航進入 $\to$ 8mm微小姿勢安定 $\to$ 垂直吸着 $\to$ 垂直微小引き上げ $\to$ 巡航移送 $\to$ 目標点垂直着手 $\to$ 待機復帰）を実行します。
